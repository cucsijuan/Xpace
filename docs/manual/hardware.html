First Edition

Changes are made periodically to the information herein; any such changes will be reported in subsequent revisions.

This manual describes the devices on the ship systems bus of the pc86 ship computer: the pilot's controls, the flight sensors, the thrusters and the main engine, the radar and the weapons, the defensive systems, the power plant, the heat and the cockpit displays, as fitted to the ship it came with. Fittings vary between ships: a program must look on the bus for what it needs before it uses it (Chapter 1).

The ship computer runs the COS disk operating system. How to use COS, its editor (EDIT) and its assembler (ASM) is described in the COS User's Guide.

Preface

Everything your ship does, it does because a program told it to. The flight assist that holds your heading, the fire control that puts the turret on the target, the warning receiver's picture and the power distributor's pips are programs running on the ship computer, a pc86 personal computer with COS, and their sources are on the ship's diskette. This manual tells you what the hardware they talk to is, register by register, so that you can read those programs, change them, and write programs of your own.

The ship's programs are good programs, but they were written for every ship and every pilot. A program written for your ship and the way you fly it can do better: a fire control that knows how a target turns hits it more often; a flight program that knows your engine runs it harder. None of this is magic. Every device does what its physics lets it do, and no more: a program can only make better use of it.

This manual assumes that you can write programs in the assembly language of the 8086 processor with the COS assembler, ASM, and that you know how a COS program uses the operating system's services. Both are described in the COS User's Guide.

  • Read Chapter 1 first: how the bus works, how a program finds a device, and the units the devices use.
  • Chapter 2 tells you how the ship's programs share the computer, and how to change one in flight. It ends with a complete resident program.
  • Chapters 3 to 7 describe the devices, one section each. Appendix A describes the programs that come with the ship.

Contents

The Ship Computer

The ship computer is a pc86 personal computer with three cards in its slots: the video card (the console screen in the cockpit), the diskette controller (one 3½-inch drive, drive A:), and the ship systems bus card, which connects the computer to the rest of the ship. It runs COS from the ship's diskette, and at start-up COS runs AUTOEXEC.BAT, which loads the ship's programs.

The processor runs about 400,000 instructions a second. That is shared by everything the computer does: the resident programs that fly the ship and work its systems, and whatever you run at the COS prompt. Appendix A says how much of it each of the ship's programs takes.

Slots and Ports

The bus card gives the ship's devices sixteen slots of sixteen ports each, from port 100h. Slot n begins at port 100h + 16 × n: slot 3 is 130h to 13Fh. A program reads a device's registers with IN and writes them with OUT, a byte at a time, with the port in DX:

    mov dx, 130h + 3        ; the radar's contacts
    in al, dx

Every device has the same first two registers:

RegisterContents
+0The device's type: a number that says what kind of device it is (the table below). A slot with no device reads 0.
+1The version of the device's registers. A later version keeps the registers of the earlier ones and adds to them.

The ship's devices are always in the same slots:

Not every ship has every device: a ship may have a laser and no turret, or no jammer. Before a program uses a device, it reads the device's type register and checks it. A program that writes to an empty slot does nothing; one that reads from it reads zeros, which may be taken for real readings.

    mov dx, 1D0h            ; a heat sink launcher?
    in al, dx
    cmp al, 14
    jne no_heat_sinks

How the Devices Work

The devices and the computer take turns, sixty times a second. At each step:

  1. Every device puts its new readings in its registers: the controls where the pilot holds them, the inertial unit's new sample, the radar's track.
  2. The inertial unit raises the sample interrupt, IRQ 5, and the computer runs for 1/60 of a second.
  3. Every device looks at what the program wrote to it during the step, and does it: the thrusters push, the turret's servos turn, the laser fires.

So a device sees what the program wrote only at the end of the step, and if a register was written more than once, it sees the last value. Writing a register is what tells the device to act: the laser fires in a step in which its fire register was written, whatever was in it before. A word is written as two bytes, the low byte first; write both bytes in the same step.

A device's readings do not change during a step. A program that reads a register twice in the same step reads the same value.

The Sample Interrupt

IRQ 5 comes from the inertial unit, sixty times a second, as soon as its new sample and all the other devices' readings are in their registers. It is interrupt 0Dh. Programs that have to do something every step (flying the ship, aiming a turret) do it there: see Chapter 2.

The interrupt line is enabled at the interrupt controller (port 21h, bit 5 clear) by the first program that takes it. The flight program acknowledges each sample by reading the inertial unit's status register (+14); no other program should read that register.

Memory Windows

Some devices have more to give than sixteen ports can hold: the radar's contacts, the warning receiver's emitters, the screens. They keep it in memory, in a window above the video memory, in segment D000h. The device's registers say where (a segment and an offset), and a program should take the addresses from there. In this ship:

AddressContents
D000:1000The radar's contact table (Chapter 4)
D000:1100The radar's track
D000:1200The display card's screen table (Chapter 7)
D000:1300The warning receiver's emitter table (Chapter 5)
D000:1400The whole rating plate (Chapter 3)
D000:2000The screens' memory, from here up

These are written by the devices at each step. A program reads them, and writes only the screens' memory.

The Ship's Programs

The programs that fly the ship and work its systems are resident COS programs: started from AUTOEXEC.BAT, each takes the sample interrupt, stays in memory (COS function 31h) and gives the prompt back. From then on each does its work at every step, inside the interrupt, and the console stays free for you. The ship's AUTOEXEC.BAT is:

@ECHO OFF
FLIGHT
FIRECTL
RWR
POWER

Each one can be taken out of memory with OFF (FIRECTL OFF), and started again by its name.

The Interrupt Chain

Every program that takes IRQ 5 keeps the address of the handler that had it before, and calls it first: the programs form a chain, the last one started at its head, and every one of them runs at every step. At the end of the chain is the BIOS's own handler, which ends the interrupt at the interrupt controller. A handler on the chain looks like this:

on_irq:
    pushf                   ; as if the interrupt had called it
    call far [cs:old_irq]   ; the programs before this one first
    push ax
    ...                     ; its own work
    pop ax
    iret

The ship's programs follow a convention, so that they can find each other on the chain:

OffsetContents
100hA near jump to the start of the program (jmp near start, three bytes).
103hThe program's signature: six characters, the first two XP.
109hThe handler it calls: the offset, then the segment (old_irq).

To take itself out of memory, a program follows the chain from the interrupt vector: at each program on it, it compares the signature with its own, and if it is not its own, goes on to the handler at 109h. Found, the program before it is made to call what it called (its word at 109h is changed), or, if it is the first, the vector is. That way any of them can leave, wherever it is on the chain. A handler that does not follow the convention ends the search: programs started after it cannot be taken out until it is.

A handler on the chain must keep to a few rules:

  • It must not call COS (interrupt 21h): the interrupt may have stopped COS itself in the middle of a call. BIOS calls are safe.
  • It must be quick. Every handler on the chain runs at every step, and together they share 1/60 of a second with the program at the prompt. A handler that takes the whole step leaves nothing for the others.
  • It must keep every register it uses, and DS: set DS from CS on entry, if it needs its own data.

Changing a Program in Flight

The sources of the ship's programs are on the ship's diskette (FLIGHT.ASM, FIRECTL.ASM, RWR.ASM, POWER.ASM). To change one, edit its source with EDIT, assemble it with ASM, and start the new program in place of the old one. Assemble it to a new name, so that the program that works stays on the diskette:

A:\>edit firectl.asm

A:\>asm firectl.asm new.com

A:\>firectl off
Fire control removed: radar off.

A:\>new
Fire control resident: scope on RADAR, page on WEAPON.

While ASM works (about half a minute for FIRECTL.ASM in flight: the resident programs keep their share of the processor) the old program goes on working. Between FIRECTL OFF and NEW the radar is off.

When the new program works as you wish, copy it over the old one (COPY NEW.COM FIRECTL.COM), and AUTOEXEC.BAT starts it next time.

If the flight program stops writing the thrusters' commands for a tenth of a second, the thrusters take the pilot's controls directly, with no flight assist (Chapter 3). A flight program that hangs inside the interrupt hangs the whole computer: then only the computer's reset brings the ship's programs back.

The Ship's Diskette

What programs write on the ship's diskette stays on it. It is the ship's own, and it goes with the ship: a ship lost is its diskette lost. Send a copy to your insurer when you have changed the ship's programs; a replacement ship comes with the last copy you sent, or, if you sent none, with the diskette the ship was delivered with.

A Sample Program

Appendix B lists COOL.ASM, a complete resident program in thirty lines of work and a page of installing and removing. It watches the ship's heat and throws a heat sink when the ship runs hot. Type it with EDIT, assemble it and start it:

A:\>asm cool.asm

A:\>cool
COOL resident.

It goes on the chain like the ship's programs, and COOL OFF takes it out. The parts that install it and take it out of the chain (start, remove, find_resident) can be used as they are in programs of your own; change the signature.

The main engine gives what its own controller decides of what is asked.

Main Engine1F0h · type 17

The main engine, its controller and its cooling unit. The engine gives the forward thrust the thrusters' +12 command asks for, as its controller allows. The controller is built into the engine and works on its own: it reckons the core's temperature from the coolant's, as the cooling unit reports it, and from the thrust it gives, and when it reckons the core too hot it cuts the engine out until the core has cooled to its resume temperature. Held at full thrust, the engine pulses. The ship's programs cannot switch the controller off.

The cooling unit carries the core's heat to the radiators. More power to the engines (Chapter 6) drives it harder; its boost harder still, drawing power and making the radiators glow brighter, which heat-seeking missiles see.

RegisterContents
+2 wordThe core's temperature as the controller reckons it (°C)
+4 wordThe coolant's temperature as the cooling unit reports it (°C)
+6Status: bit 0 cut out, bit 3 cooling boost, bit 4 calibration mode, bit 5 worn, bit 6 failed. Write: the cooling unit's controls, bit 0 boost, bit 7 calibration mode.
+7Thrust given, 0 to 255 of the engine's rating
+8 wordThe controller's cut-out temperature (°C)
+10 wordThe controller's resume temperature (°C)
+12 wordThe diagnostic port: an address in the controller's program memory (write)
+14The byte at that address, a step after it was written
+15The service port (write; for the maker's service equipment)

In calibration mode the cooling unit reports, at +4, whatever is written there, so that its reading can be checked against a known temperature. Leave it off in flight.

An engine run hotter than its safe temperature wears and gives less thrust, for good (bit 5). Hotter still it fails (bit 6), and the ship with it. Thrust beyond what the hull is rated for breaks the hull. The controller keeps the engine within its rating; nothing keeps it there if the controller is misled.

Radar130h · type 4

A pulse-Doppler radar looking in a cone ahead of the ship. Searching, it sweeps the cone twice a second and writes what it sees into a table of contacts. Told to lock one of them, it tracks it sixty times a second and writes where it is.

What it measures is only as good as the echo against the noise. An echo falls with the fourth power of the range and grows with the size of the target, so its errors grow with the range; jamming adds noise, and rocks near a target echo with it. The track gives only the target's position: its velocity is for the program to work out, by following the positions.

RegisterContents
+2Mode (write: 0 off, 1 on)
+3Contacts in the table
+4Sweeps so far, counting up
+51 while a target is locked
+6 wordWrite: lock the contact with this id; 0 lets the target go
+8 wordThe id of the locked target
+10 wordThe segment of the tables
+12 wordThe offset of the contact table
+14 wordThe offset of the track

The Contact Table

Up to sixteen contacts of sixteen bytes, written at every sweep:

OffsetContents
+0 wordThe contact's id
+2 wordRange (m)
+4 wordAzimuth (binary angle)
+6 wordElevation
+8 wordClosing speed, from the Doppler (1/8 m/s)
+10Flags: bit 0 locked, bit 1 a jammer's strobe

A jammer's noise is heard from its direction, but gives no range: it is written after the echoes as a strobe, with range 0 and flag bit 1, and cannot be locked.

The Track

OffsetContents
+0 wordThe id of the target
+2 wordIts position to the right (1/4 m, from the turret's pivot)
+4 wordUpward
+6 wordForward
+8 wordThe echo's signal-to-noise ratio (dB)
+14 wordRange (m)

The tracker follows what is in its gate, a small cell of angle, range and Doppler round where the target was, moved on at the velocity it has been following. It measures the middle of all the echoes in it and keeps the lock on the strongest. Chaff that sits in the gate pulls the track toward itself and may take the lock; a repeater jammer can walk the gate away. A target lost at the edge of the cone or to a weak echo is taken back by itself if it is seen again within three seconds, near where the gate would be.

Gimballed Turret140h · type 5

A kinetic cannon on a gimbal under the ship. The program writes the angles it wants; servos turn the turret toward them, following how fast the asked-for angles move, within a top rate and an acceleration. Every round leaves a little off the bore, more when the barrel is hot, and kicks the mount.

RegisterContents
+2 wordAzimuth wanted (write; binary angle, 0 straight ahead)
+4 wordElevation wanted (write)
+6 wordAzimuth now
+8 wordElevation now
+10 wordMuzzle speed (m/s)
+12Write 1: fire in this step
+13Status: bit 0 ready, bit 1 at a limit of the gimbal, bit 2 too hot to fire
+14Barrel heat, 0 to 255
+15Rounds fired, counting up

The gun fires while the program writes +12 at every step. A round flies at the muzzle speed on top of the ship's own velocity; at 2 km it takes nearly two seconds to arrive, and a target that turns meanwhile is missed. Where to point is the program's to work out.

Missile Launcher160h · type 7

The launcher carries radar-guided missiles and heat-seeking missiles. A radar missile is guided by the launcher's datalink: at every step the radar keeps its track, the datalink sends the missile where the radar puts the target. Without the track it flies on what it last knew, and is lost after two seconds of silence. A heat seeker needs neither: its own head follows the brightest heat in its view.

Powered, the head of the heat seeker on the rail looks along the launcher's boresight, or where the radar's target is if there is a lock; heat in its view makes it growl in the pilot's headset, and held for a moment it locks on. A heat seeker can be fired at any time: it leaves looking where the head on the rail looked.

RegisterContents
+2Radar missiles left
+3Missiles in flight
+4Status: bit 0 a radar missile ready to fire, bit 1 the radar has a lock, bit 2 a heat seeker ready, bit 3 its head sees heat, bit 4 its head is locked on
+6Write 1: fire a radar missile at the radar's target; 2: fire a heat seeker
+7Bit 0: power the heat seeker's head (write)
+8 wordThe newest missile's time to go (1/8 s; 0FFFFh unknown)
+10Its status: bit 0 guided, bit 1 no word from the ship (or its head sees nothing), bit 2 lost
+11How it went: 0 none, 1 flying, 2 hit, 3 missed
+12 wordIts fuel: the speed change it has left (m/s)
+14Heat seekers left
+15The newest missile's kind: 1 radar, 2 heat seeker

The datalink sends the radar's track, whatever the tracker follows: if chaff has taken it, the missile goes for the chaff. The next heat seeker brought to the rail after a launch starts with its head off.

Pulse Laser190h · type 11

A pulse laser fixed along the nose: the pilot aims it by pointing the ship. While the program writes the fire register at every step it fires a pulse at a time, from its emitters in turn. A pulse is a bolt that flies at the bolt speed on top of the ship's velocity, so far out the pilot has to lead the target. Every pulse takes power from the weapons capacitor (Chapter 6) and heats the emitters; too hot, the laser stops until they cool.

RegisterContents
+2Status: bit 0 ready, bit 1 no power, bit 2 too hot
+3Heat, 0 to 255
+4Write 1: fire in this step
+5Pulses fired, counting up
+6 wordBolt speed (m/s)
+8 wordThe lead point to the right (write; 1/4 m, from where the radar measures)
+10 wordUpward (write)

+14Bit 0: show the lead circle in this step (write)

The sight is the program's: it works out where a pulse fired now would meet the target, writes that point to +8 to +12 and bit 0 of +14 at every step, and the head-up display draws a circle there and a pipper where the pulses go at that range. The pilot puts the pipper on the circle and fires.

Radar Warning Receiver170h · type 8

Antennas round the hull hear the radars whose beams light the ship, from every side; the receiver only listens. For each radar it hears it works out a bearing, from the antennas; a range, guessed from the strength of the signal and the power its library lists for that kind of radar; a type, from the signature; and whether the radar has the ship locked. A searching radar is heard only as its beam passes, and stays in the table for a while after.

The same box has a missile approach warner: it sees the plume of a burning missile motor coming at the ship. A missile that has burnt out coasts unseen.

Radar Jammer1E0h · type 16

A jammer fills the radars' receivers with noise, so that an echo has to be stronger to be seen and is measured worse. The noise falls with the square of the distance and the echo with the fourth power, so close in a radar burns through. Models with deception also hear a radar tracking the ship and send its pulses back, stronger than the ship's own echo, and walk the copy away in range, taking the radar's gate with it; then they stop, and the gate is left on nothing.

The antenna sends all round, or, aimed, puts much more into a beam toward the bearing the program gives (the radar that has the ship locked, from the warning receiver). Sending, the jammer draws from the systems capacitor, and all it draws ends as heat. And it is heard: warning receivers far beyond the range it hides the ship at show it as a J.

+4 wordAzimuth to aim at (write; binary angle)
+6 wordElevation to aim at (write)
+8Write 0: send all round; 1: aim at +4 and +6
+9Status: bit 0 sending, bit 1 short of power, bit 2 deceiving a tracking radar
+10The power it gets, 0 to 255

Power Distributor1B0h · type 15

The power plant and its distributor. The distributor shares the plant's power among three capacitors, by the program's setting: systems (the shield and the jammer), engines (the thrusters and the cooling unit's boost) and weapons (the laser). The setting is in twelve half pips, at most eight on one. A capacitor fills at its share of the plant while it has room, and empties as what hangs on it draws: a share too small for what draws on it runs dry, and then the shield builds back slowly, the thrusters push only as hard as the power coming in lets them, and the laser waits. Part of the power drawn ends as heat.

RegisterContents
+2Half pips to systems
+3Half pips to engines
+4Half pips to weapons
+6The systems capacitor, 0 to 255 full
+7The engines capacitor
+8The weapons capacitor

To change the setting, write all three of +2, +3 and +4, the weapons last: writing +4 sets the three. A setting that does not add up to twelve, or puts more than eight on one, is ignored.

Heat Sink Launcher1D0h · type 14

The ship's heat, and the launcher of heat sinks. What the systems give, what the power plant wastes and what the weapons and the jammer leave in the ship warms it; the radiators give it off, the more the hotter it is. Past 100% the ship cooks: its hull wears, and the shield does not help. A hot hull shines on heat seekers. A heat sink soaks heat up for a few seconds and is thrown away with it.

RegisterContents
+2Heat, in percent (to 255)
+3Heat sinks left
+4Write: bit 0 throw a heat sink
+5Status: bit 0 a heat sink working, bit 1 over 100%

Display Card150h · type 6

The cockpit's screens, other than the computer's console, with their memory in segment D000h. Each screen has a name (RADAR, WEAPON, RWR, FLIGHT), a size and a mode; a program finds the screen it draws on by its name, in the screen table. A cockpit may have more screens or fewer: a program that finds no screen of its name works the same, unseen. Version 3.

RegisterContents
+2 wordThe segment of the table and the screens' memory
+4 wordThe offset of the screen table
+6Screens in the table
+7The screen of interest: the one the pilot picked (0FFh, none)
+8Bezel keys pressed so far, counting up
+9The last key: 1 zoom in, 2 zoom out, 3 sound
+10The screen it was pressed for

A program looks at +8 now and then: when it has moved on and +10 is its own screen, the key in +9 is for it. What the key does is the program's to decide.

The Screen Table

Sixteen bytes a screen:

OffsetContents
+0Name: six characters, filled with spaces
+6Mode (the program writes it): 0 text, 1 graphics
+7Columns (text)
+8Rows (text)
+10 wordWidth (graphics, pixels)
+12 wordHeight (graphics, pixels)
+14 wordThe offset of the screen's memory (a multiple of 16)

In text mode the memory holds a character and an attribute for each cell, as the video card's colour text mode does. In graphics mode it holds two bits a pixel (off, dim, half, bright), four pixels to a byte with the leftmost in the top bits, width/4 bytes a row. The screens' phosphor glows on for a moment after a pixel goes off.

FLIGHTFlight control

Flies the ship from the pilot's controls. With flight assist on, the stick asks for turn rates and the throttle for a forward speed, the strafe controls for speeds across, up to what the rating plate says the ship can do; let go, and the ship stops turning and drifting. With flight assist off, the controls drive the thrusters directly and the ship keeps its motion. Safe turns ask only for the turn rates at which the ship's path can follow its nose. Its page is on the FLIGHT screen, if the cockpit has one. It acknowledges the inertial unit's samples. About 5% of the processor.

Buttons: flight assist, safe turns, boost (the main engine's cooling boost).

FIRECTLFire control

Works the radar, the turret, the laser and the missile launcher. Target ahead locks the contact nearest the middle of the view, or lets the target go; next target locks the next one. With a target locked it smooths the radar's positions with an alpha-beta filter, which gives the target's velocity, and works out where a round fired now meets the target if it flies on straight; it points the turret there, or writes the laser's lead point. Next weapon steps through the cannon, the radar missiles, the heat seekers and the laser, as the ship has them. Its radar scope is on RADAR, its page on WEAPON. About a third of the processor.

Buttons: target ahead, next target, fire, next weapon.

RWRThreat warning

Draws the warning receiver's picture on the RWR screen, works the countermeasures dispenser and the jammer, and aims the jammer at the radar that has the ship locked.

Buttons: chaff, flare, jammer (off, noise, deception if the model has it).

POWERPower manager

Moves the power distributor's pips: a pip to systems, engines or weapons, from the others; evens them out; throws heat sinks.

Buttons: systems, engines, weapons, even out, heat sink.

Signatures

ProgramSignature at 103h
FLIGHTXPFL15
FIRECTLXPFC12
RWRXPRW15
POWERXPPW11

The last two characters are the version. Change them when you change a program, so that a new version is not taken for the old one; a program that finds another version of itself on the chain does not take it out.

What It Does

At every step it reads the ship's heat; at 100% or more, with no heat sink working, it throws one. It is a resident program on the sample interrupt, and follows the convention of Chapter 2, so it can be taken out of the chain wherever it is (COOL OFF).

The Listing

; COOL.ASM - throws a heat sink when the ship runs hot
;
;   COOL        stays resident
;   COOL OFF    takes it out of memory

org 100h

HEAT        equ 1D0h
TYPE_HEAT   equ 14
TOO_HOT     equ 100                 ; percent
IRQ_VECTOR  equ 0Dh
IRQ_BIT     equ 20h

    jmp near start

; ---------- the resident part ----------

signature   db 'XPCOOL'             ; 103h
old_irq     dw 0, 0                 ; 109h

on_irq:
    pushf
    call far [cs:old_irq]           ; the programs before this one first
    push ax
    push dx
    mov dx, HEAT + 5                ; a sink already working?
    in al, dx
    test al, 1
    jnz .done
    mov dx, HEAT + 2
    in al, dx
    cmp al, TOO_HOT
    jb .done
    mov dx, HEAT + 4                ; throw one
    mov al, 1
    out dx, al
.done:
    pop dx
    pop ax
    iret

resident_end:

; ---------- installing and removing ----------

start:
    mov si, 81h
.blank:
    lodsb
    cmp al, ' '
    je .blank
    and al, 0DFh
    cmp al, 'O'
    je remove

install:
    call find_resident
    jne .new
    mov dx, msg_already
    jmp quit_message
.new:
    mov dx, HEAT
    in al, dx
    cmp al, TYPE_HEAT
    je .hook
    mov dx, msg_no_device
    jmp quit_message
.hook:
    mov ax, 3500h + IRQ_VECTOR
    int 21h
    mov [old_irq], bx
    mov [old_irq + 2], es
    mov dx, on_irq
    mov ax, 2500h + IRQ_VECTOR
    int 21h
    in al, 21h                      ; IRQ 5 on at the interrupt controller
    and al, 0FFh - IRQ_BIT
    out 21h, al
    mov es, [2Ch]                   ; the environment is not needed
    mov ah, 49h
    int 21h
    mov dx, msg_installed
    mov ah, 09h
    int 21h
    mov dx, (resident_end - $$ + 100h + 15) / 16
    mov ax, 3100h
    int 21h

remove:
    call find_resident
    je .found
    mov dx, msg_not_running
    jmp quit_message
.found:
    push ds                         ; out of the chain
    cli
    mov ax, [es:old_irq]
    mov dx, [es:old_irq + 2]
    cmp word [prev_seg], 0
    je .first
    mov ds, [prev_seg]              ; the program before calls what we called
    mov [109h], ax
    mov [10Bh], dx
    jmp .unlinked
.first:
    mov ds, dx                      ; or the vector does
    mov dx, ax
    mov ax, 2500h + IRQ_VECTOR
    int 21h
.unlinked:
    sti
    pop ds
    mov ah, 49h                     ; free the resident copy
    int 21h
    mov dx, msg_removed
    jmp quit_message

; ZF set and ES the resident copy if it is on the chain; [prev_seg] the
; program before it (0: it is first)
find_resident:
    mov word [prev_seg], 0
    mov ax, 3500h + IRQ_VECTOR
    int 21h
.next:
    mov si, signature
    mov di, si
    mov cx, 6
    repe cmpsb
    je .done
    cmp word [es:103h], 'XP'        ; another ship's program: go on
    jne .no
    mov [prev_seg], es
    les bx, [es:109h]
    mov ax, es
    or ax, bx
    jnz .next
.no:
    or al, 1                        ; ZF = 0
.done:
    ret

quit_message:
    mov ah, 09h
    int 21h
    mov ax, 4C00h
    int 21h

prev_seg        dw 0
msg_installed   db 'COOL resident.', 13, 10, '$'
msg_already     db 'COOL is already resident.', 13, 10, '$'
msg_not_running db 'COOL is not resident.', 13, 10, '$'
msg_removed     db 'COOL removed.', 13, 10, '$'
msg_no_device   db 'COOL: no heat sink launcher on the bus.', 13, 10, '$'

Units

Angles 65536 to the turn; rates 1/1024 rad/s; speeds 1/8 m/s; radar positions 1/4 m; ranges m; controls and commands ±32767. Words low byte first. IRQ 5 (interrupt 0Dh) sixty times a second.
